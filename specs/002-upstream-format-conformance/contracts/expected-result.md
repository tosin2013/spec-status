# Contract: a fixture's `expected.json`

Each conformance fixture directory holds an `expected.json` written by **hand count**, never generated by spec status. The conformance runner compares only the fields present in this file with spec status's report, so unrelated JSON fields can change without breaking fixtures.

```json
{
  "pins": ["spec-kit@v1.2.0", "speckit-roadmap@v0.1.0"],
  "origin": "template-filled",
  "counted_by": "implementer, 2026-11-07",
  "outcome": "report",
  "exit": 0,
  "items": [
    {"id": "001", "status": "implemented", "active": true,
     "dependencies": [],
     "tasks": {"checked": 3, "total": 34}},
    {"id": "002", "status": "planned", "active": true,
     "dependencies": [{"id": "001", "state": "unfinished"}]}
  ],
  "summary": {
    "total_items": 2, "active_items": 2, "verified_active_items": 0,
    "blocked_count": 1, "human_review_count": 0,
    "tasks": {"checked": 3, "total": 34, "files_read": 1}
  },
  "diagnostics": [
    {"code": "SS_DEPENDENCY_BLOCKED", "item": "002"}
  ]
}
```

## Rules

- `outcome` and `exit` are required. `exit` is the exit code at the default threshold (`error`).
- `items` lists every item in document order, with `id`, `status`, and `active`. `dependencies` and `tasks` are compared when present.
- `summary` fields are compared when present.
- `diagnostics` is compared as a multiset of `(code, item)` pairs: every listed pair must occur, and no other pair may occur. Messages and lines are not compared.
- For a fatal fixture, `outcome` is `fatal` and `fatal` gives `{"code": …, "path": …, "line": …}`. `items` and `summary` are omitted.
- `counted_by` records who counted and when, because the hand count is the oracle (constitution Article I).
